# 学生2车辆主要部件标注规范

本Demo把原始模型类别归并为10个主要类别，以便学生2整理数据、标注和验证。原模型的左右与前后细分类保留在输出中；左右相互矛盾的重复区域不会被强行确定侧别。

| 项目类别ID | 编码 | 中文 | 原始Carparts-seg类别ID |
| --- | --- | --- | --- |
| 0 | front_bumper | 前保险杠 | 8 |
| 1 | back_bumper | 后保险杠 | 0 |
| 2 | hood | 引擎盖 | 16 |
| 3 | trunk | 后备箱或尾门 | 20、21 |
| 4 | door | 车门 | 1、3、6、9、11、14 |
| 5 | front_light | 前车灯 | 12、13、15 |
| 6 | back_light | 后车灯 | 4、5、7 |
| 7 | glass | 挡风玻璃 | 2、10 |
| 8 | mirror | 后视镜 | 17、19 |
| 9 | wheel | 车轮 | 22 |

原始类别18 `object` 不作为明确部件参加损伤匹配。类别顺序以 [Ultralytics官方Carparts-seg配置](https://docs.ultralytics.com/datasets/segment/carparts-seg/)为依据。

标注时只描绘照片中实际可见的部件轮廓，沿真实边界绘制多边形；遮挡后不可见的区域不补画。相邻车门、车灯和车轮分别标注为不同实例。同一部件不因损伤而拆成多个实例。车窗与金属门板的边界要按选用数据集的定义一致处理，不能在不同图片中随意改变范围。

左右方向相对于车辆自身行驶方向确定，不能按图片左右决定。镜像翻转的数据增强需要同步交换左右标签；10类合并数据没有左右类别，避免了此项歧义。无法判断的细分类采用前车门、后车门等通用标签，并记录不确定性。

YOLO分割标签每个实例一行：`class_id x1 y1 x2 y2 ... xn yn`，坐标除以原图宽高归一化到0至1，至少三个顶点。损伤框接口使用像素坐标，两者格式不同。

同一车辆的近似照片应放入同一数据划分，避免同一车辆重复照片同时进入训练集和测试集。复现公开数据时保留公开train、val、test划分。只有明确人工检查后确认无目标的图片才能作为负样本；没有标签文件的图片不自动视为负样本。

`scripts/prepare_parts10.py`可把公开23类YOLO分割数据转换成10类，并记录每个划分的图片数与部件实例数。使用完整原始数据目录执行：

```powershell
.venv/Scripts/python.exe scripts/prepare_parts10.py --source C:/data/carparts-seg --output C:/data/parts10
.venv/Scripts/python.exe scripts/train_parts.py --data C:/data/parts10/parts10.yaml --device 0 --epochs 50
```

这两步是后续自行训练的方法，当前交付没有声称已人工标注或重新训练该数据集。
