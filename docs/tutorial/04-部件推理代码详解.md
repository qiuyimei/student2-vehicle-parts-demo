# 04 部件推理代码详解

本章沿着一次真实调用读代码。主要文件为[ai/pipeline.py](../../ai/pipeline.py)和[ai/parts.py](../../ai/parts.py)。先运行过Demo，再读每段代码，会更容易对应到页面上的结果。

## 第一步 创建Pipeline

```python
from ai.pipeline import Pipeline
pipeline = Pipeline()
```

构造函数设置CPU线程上限，读取`models/parts.pt`，并创建推理锁。锁让同一服务中的模型调用按顺序执行，避免多个请求同时操作模型。部件模型初始化时加载；损伤模型先设为None，只有auto模式第一次调用时才加载。

“加载模型”是读取已经训练好的参数；没有反向传播，没有优化器更新，不能将这一步叫作训练。

## 第二步 读取并纠正照片方向

在网页接口中，服务器先用Pillow读取图片，再调用：

```python
image = ImageOps.exif_transpose(source).convert('RGB')
```

手机照片可能通过EXIF记录旋转方向。先纠正方向，外部损伤框和部件识别才有统一坐标系。接口没有把原图永久缩成640像素，而是让YOLO内部完成推理尺寸处理，并把返回结果映射回原图。

## 第三步 转成模型输入

`predict`将Pillow的RGB图像转成NumPy数组，再用OpenCV转换到BGR顺序。然后调用`_run`：

```python
model.predict(image, conf=conf, imgsz=640,
              device='cpu', verbose=False, retina_masks=True)
```

`conf`是保留候选的置信度阈值；`imgsz`是内部推理尺寸；当前Demo固定CPU；`retina_masks=True`用于返回与原图对应的高分辨率分割掩膜。

阈值是实验条件，不是精度指标。降低阈值可能让更多部件显示出来，也可能增加误检。

## 第四步 取出四种模型结果

| 模型属性 | 本工程读取方式 | 含义 |
| --- | --- | --- |
| boxes.xyxy | 转为CPU上的NumPy数组 | 原图像素框 `[x1,y1,x2,y2]` |
| boxes.conf | 转为浮点数 | 原始类别预测置信度 |
| boxes.cls与names | 类别ID转成名称 | 例如front_bumper |
| masks.data | 转成布尔数组 | 部件区域内为True，区域外为False |

没有检测结果时，返回空列表或None，而不是填入固定的演示部件。可以更换自己的图片验证这一点。

## 第五步 排除通用类别

`PART_LABELS`列出明确支持的部件标签。原始`object`不代表确定的车身部件，因此不进入后续关联。

细分类仍保留，例如左右前车灯；`group_for`再把它们归为前车灯这个业务类别。`part`和`group`分别承担细分类和10类业务展示，不能混为一个字段。

## 第六步 合并重复实体

`merge_duplicate_parts`先按置信度降序处理。同一个部件家族的两个区域，如果掩膜IoU至少0.65，就认为可能是同一实体的重复预测。保留高分候选的几何区域，并记录`candidateClasses`与`mergedDetections`。

若同一区域一条预测是左前门，另一条是右前门，就把输出变成通用前门，并标记`labelStatus=ambiguous_label`。程序保留了矛盾证据，没有根据照片位置自行编造左右方向。

两个分离的车轮不会因为同属wheel就合并；门板和保险杠也不会因为空间重叠就当成同一类别合并。相关边界条件在`tests/test_parts.py`里。

## 第七步 形成部件实例

每个合并后部件获得`instanceId`，例如`part-2`。其他字段包括：

- `part`与`partLabel`：编码和中文名称。
- `group`与`groupLabel`：10类业务类别。
- `bbox`：部件矩形包围框。
- `areaPixels`：部件掩膜的像素数量。
- `polygons`：经过简化的轮廓，供展示或接口传输。
- `rawClass`与`candidateClasses`：原始最高分标签及合并时出现的标签。

面积计算使用布尔掩膜，不是把简化轮廓重新绘制后计算。合并后的置信度仍是最高原始预测分数，不是重新训练或校准过的通用类别概率。

## 第八步 根据模式取得损伤输入

`parts`模式没有损伤。`external`模式验证并复制用户明确传入的损伤数组。`auto`模式读取damage.pt，让公开模型生成损伤框与掩膜。随后每个损伤都交给同一个`match_damage`函数。

## 第九步 保存图片与JSON结构

每次推理生成一个UUID，避免不同请求覆盖同名图。图片保存在`data/media/`：原图、部件标注图、损伤关联图。返回URL指向这些文件；直接下载的JSON本身不包含图片二进制。

如果把JSON发给另一台电脑，`/media/...`这样的本地服务URL不会自动带走图片。提交个人成果时应同时保存标注图和结果JSON，或使用命令行输出目录中的命名图片。
