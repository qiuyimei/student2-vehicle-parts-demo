# 05 匹配算法逐步计算

核心函数位于[ai/matching.py](../../ai/matching.py)。本章先手算，再运行教学例子，最后回到真实图片。输入与输出字段详见[接口说明](06-接口联调与字段说明.md)。

## 第一步 认识三种面积

设损伤区域为D，某个部件区域为P，它们的交集为I。

| 名称 | 公式 | 回答的问题 |
| --- | --- | --- |
| 损伤覆盖率 | `area(I) / area(D)` | 这处损伤有多少被该部件覆盖 |
| 部件损伤占比 | `area(I) / area(P)` | 该部件可见区域有多少与损伤相交 |
| IoU | `area(I) / (area(D) + area(P) - area(I))` | 两个区域整体有多接近 |

本工程用于次级排序的`matchIou`是框IoU。掩膜分支的覆盖率与部件占比则按掩膜像素求交计算。看到IoU字段时，要先确认使用的是框还是掩膜。

## 第二步 手算小损伤位于大部件

部件框为`[0,0,100,100]`，面积10,000。损伤框为`[10,10,20,20]`，面积100，完全位于部件内。交集为100。

因此覆盖率为100/100，即100%；部件损伤占比为100/10,000，即1%；框IoU为100/(100+10,000-100)，也是1%。

如果只要求IoU很高才能匹配，这个明确位于车门内部的小损伤会被错误拒绝。因此本工程把覆盖率作为主要排序和接受条件，IoU作为次级排序依据。

## 第三步 运行不依赖模型的例子

```powershell
& .\.venv\Scripts\python.exe examples/match_without_model.py
```

第一个人为构造例子应输出`part=front_door`、`matchCoverage=1.0`、`matchIou=0.01`、`damageRatio=0.01`、`matchStatus=matched`。

第二个例子让损伤与部件完全分离，输出unknown。第三个例子把车灯破损放在车门范围内，虽然几何重叠，但类型不相容，也输出unknown。这些是教学输入，不是模型预测，更不是模型准确率实验。

## 第四步 处理真实掩膜

若损伤与部件都有mask，程序把二者转为布尔数组，用逻辑与得到交集，再数True像素。mask必须有相同的高、宽，并对应同一张已经纠正方向的原图。

损伤mask可能只是一个细小划痕，部件mask可能是不规则车门，因此不能简单用两个大矩形面积代替。真实分割分支输出`ratioMethod=mask_intersection`。

## 第五步 只有外部损伤框时怎么办

学生1可能只提供bbox。程序会建立一个与原图等大的空布尔数组，将框内像素设成True，再和部件mask求交。这个分支输出`bbox_mask_intersection`。

由于矩形内部可能包含没有损伤的背景，该比例是框区域近似，不一定等于真实受损像素比例。如果部件与损伤都没有mask，独立匹配函数可以退化为`bbox_intersection`，解释结果时应保留这种差别。

## 第六步 检查类别相容性

车灯破损要求候选编码包含light，玻璃破碎要求包含glass，轮胎异常要求包含wheel。凹陷、划痕和裂纹没有这三种专用限制。

该规则可以防止某些明显不合理的“灯破损匹配给门板”，但它相信了上游损伤类型。若上游类型本身错误，规则也可能拒绝一个几何上接近的部件，所以必须保存候选和unknown，而不能承诺完全纠错。

## 第七步 排序并决定是否接受

程序先计算全部部件候选，按覆盖率、框IoU、部件置信度依次降序排序；再从类型相容的候选中选最优。

默认最低覆盖率为0.35，即35%。无候选、无相容候选或最优覆盖率低于阈值时，返回unknown，`damageRatio`保留null。两个或更多相容候选都达到阈值时，返回`multiple_parts`，保留主部件及候选供人工复核。

0.35是演示参数，不是经维修人员认定的行业标准。后续应在人工标注的关联测试集上比较不同阈值，而不是只挑一张图调到看起来最好。

## 第八步 用真实样例核对字段

先执行：

```powershell
& .\.venv\Scripts\python.exe scripts/run_demo.py --image samples/damage-4.jpg --mode auto --output results/tutorial-runs/matching
```

打开输出JSON的`damages[0]`。在固定公开权重和默认阈值下，初版记录为front_bumper，覆盖率0.98649，部件损伤占比0.19515，框IoU0.15123。再看对应标注图片，确认橙色框确实落在预测的保险杠区域内。

这些数值来自二维预测区域，不能解释成凹陷深度、维修价格或结构安全程度。

## 第九步 做一个阈值对照

复制同一个输入，分别使用0.35与0.8的最低覆盖率。把接受数、unknown数以及人工观察到的正确和错误情况记录下来。比较时保持图片、模型、部件置信度和损伤置信度相同，才知道变化来自匹配阈值。

本章验收：能手算三个指标；能解释低IoU仍可匹配；理解unknown、多候选和语义约束；不把匹配接受数当作准确率。
