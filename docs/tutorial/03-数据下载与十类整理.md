# 03 数据下载与十类整理

本章整理的是公开数据集已有的分割标注。它不是学生新完成的人工标注，也不是损伤数据集CarDD。先保留官方23类用于复现公开部件模型，再另存一份10类标签用于后续训练。

## 第一步 分清两种数据

| 数据 | 识别对象 | 当前用途 |
| --- | --- | --- |
| Carparts-seg | 保险杠、车门、车灯等部件 | 学生2的部件模型复现、数据整理与验证 |
| CarDD | 凹陷、划痕、裂纹等损伤 | 学生1方向；当前仅使用公开权重生成联调输入 |

不要将CarDD损伤标签直接作为部件模型的类别，也不要把部件模型的mAP写成损伤识别准确率。

## 第二步 下载并校验官方快照

只复测公开部件模型时，先只解压test划分：

```powershell
& .\.venv\Scripts\python.exe scripts/download_dataset.py --subset test
```

脚本从[官方说明中的下载链接](https://docs.ultralytics.com/datasets/segment/carparts-seg/)下载ZIP到`data/downloads/`，校验整个ZIP的SHA256，再解压276张测试图片及标签到`data/datasets/carparts-seg/`。只解压test并不会减少官方ZIP的下载体积，优点是节省解压后的文件数量与空间。

本次快照的SHA256是：

```text
e2eea20030d02366b07174bcdbcc843f63791bdd53962a83e00636d15e78e41f
```

如果已经有官方ZIP，可以完全离线提取：

```powershell
& .\.venv\Scripts\python.exe scripts/download_dataset.py --source-zip 'C:\你的数据目录\carparts-seg.zip' --subset test
```

不要把10类转换数据包传给`--source-zip`，它与官方原始ZIP不是同一个文件，SHA256校验会拒绝。

## 第三步 检查目录和数量

```powershell
(Get-ChildItem .\data\datasets\carparts-seg\images\test -File).Count
(Get-ChildItem .\data\datasets\carparts-seg\labels\test -File).Count
```

两项都应为276。目录结构为：

```text
data/datasets/carparts-seg/
├── images/test/某图片.jpg
├── labels/test/某图片.txt
└── download-test-manifest.json
```

图像和标签通过同名文件对应，例如`car.jpg`对应`car.txt`。没有目标的图片可能有空标签文件；丢失标签文件不应自动当作正确的负样本。

## 第四步 读懂一条分割标签

YOLO分割标签每行表示一个实例，格式为：

```text
class_id x1 y1 x2 y2 x3 y3 ... xn yn
```

至少需要三个顶点。坐标是除以图像宽高后的0至1归一化值。例如，宽800、高600的图片，顶点`(200,150)`写成`(0.25,0.25)`。这不同于接口使用的像素坐标框`[x1,y1,x2,y2]`。

多行标签表示多个部件实例。不能因为两个车轮属于同一类别，就把它们的多边形连成一个大区域。

## 第五步 准备完整数据

转换10类或训练时需要train、val、test三个划分，执行：

```powershell
& .\.venv\Scripts\python.exe scripts/download_dataset.py --subset all
```

脚本会复用已经校验的ZIP，并提取完整官方划分：训练3,156张、验证401张、测试276张，共3,833张。这些数量与本次使用的快照一致；如果上游数据版本变化，先核对快照，不要直接覆盖记录中的数字。

## 第六步 把23类归并为10类

```powershell
& .\.venv\Scripts\python.exe scripts/prepare_parts10.py --source data/datasets/carparts-seg --output data/datasets/parts10
```

`--output`必须是尚不存在的新目录。脚本不会直接覆盖已有的转换数据。要做第二次实验时，可以改成`data/datasets/parts10-v2`，而不是随意删掉旧数据。

映射规则如下：

| 新ID | 新类别 | 原始ID |
| --- | --- | --- |
| 0 | front_bumper | 8 |
| 1 | back_bumper | 0 |
| 2 | hood | 16 |
| 3 | trunk | 20、21 |
| 4 | door | 1、3、6、9、11、14 |
| 5 | front_light | 12、13、15 |
| 6 | back_light | 4、5、7 |
| 7 | glass | 2、10 |
| 8 | mirror | 17、19 |
| 9 | wheel | 22 |

原始ID18的通用object被排除。其他实例只改变类别ID，多边形顶点不变。训练、验证、测试文件不重新混合。

## 第七步 检查转换输出

```powershell
Get-Content .\data\datasets\parts10\parts10.yaml -Encoding utf8
Get-Content .\data\datasets\parts10\conversion-manifest.json -Encoding utf8
```

YAML应有10个类别以及train、val、test路径。转换清单应保留三个划分的图片数，并统计每类实例数。本次结果副本见[数据整理计数](../../results/dataset10-counts.csv)。

请抽查至少一张正面、一张侧面、一张背面图片，确认图像与标签同名，部件边界没有因转换改变。注意“类别映射完成”不能证明原始标注完全正确，仍应保留有疑问的样例。

## 第八步 使用Release中的现成10类数据包

如果只想取得本次整理结果，可以从[Release](https://github.com/qiuyimei/student2-vehicle-parts-demo/releases/latest)下载10类数据集ZIP。解压后找到`parts10/parts10.yaml`，以后将它的绝对路径传给训练与10类模型验证脚本。

这个包不能代替原始23类数据去复测公开23类模型，因为类别ID语义已经改变。

## 第九步 后续自己采集与标注

采集时记录照片来源、车辆角度、光照与遮挡；标注可见部件轮廓，不补画被遮住的部分。左右依据车辆自身行驶方向判断，不能直接按图片左右判断。相同车辆的相似照片应放进同一数据划分，避免信息泄漏。

细则见[部件标注规范](../部件标注规范.md)。本次交付完成公开标签的整理与映射，没有声称已经完成新的门店采集或人工标注。

本章验收：能区分原始23类与转换10类；能找到下载校验记录和转换清单；解释至少一条分割标签；没有把test划分挪去训练。
