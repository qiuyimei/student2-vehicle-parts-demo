# 08 自有模型训练与验证

这是后续可选阶段。本次交付复现了公开权重，没有重新训练。下面说明未来有算力与数据时怎样实际训练、验证和接入，不提供不存在的训练日志或成绩。

## 第一步 先确定训练问题

如果目标只是完成学生2的基本独立Demo，前面已能复现。若要形成自有模型实验，应先写清类别、数据版本、划分、初始化权重和对比方案。

本工程准备的是10类部件分割数据；使用它训练后，类别顺序必须与`parts10.yaml`一致。不能把原始23类训练结果与新10类结果不加区分地并列成“提升”。

## 第二步 准备10类数据

完成[数据整理章节](03-数据下载与十类整理.md)，或者解压Release中的10类数据包。确认YAML路径和三个划分都存在：

```powershell
$partsData = (Resolve-Path .\data\datasets\parts10\parts10.yaml).Path
Get-Content -LiteralPath $partsData -Encoding utf8
```

`Resolve-Path`失败说明路径还没准备好，不应直接开始训练。来自其他电脑的YAML若含绝对路径，需要改为当前数据根目录；Release数据包里的YAML可用其自身目录作为根目录，但仍建议传入YAML绝对路径。

## 第三步 检查算力

```powershell
& .\.venv\Scripts\python.exe -c 'import torch; print(torch.__version__); print(torch.cuda.is_available())'
```

本教程安装的CPU版本通常返回False。CPU能运行训练入口，但完整训练可能耗时很长，不能据此承诺某台电脑的完成时间。GPU训练需要按[PyTorch官方安装说明](https://pytorch.org/get-started/locally/)另建匹配显卡与驱动的CUDA环境，再进行导入检查。

## 第四步 先验证训练流程能启动

先用一个epoch检查数据读取、类别与保存流程：

```powershell
& .\.venv\Scripts\python.exe scripts/train_parts.py --data $partsData --epochs 1 --device cpu --output runs/student2-sanity
```

一个epoch只是运行检查，不是正式精度实验。默认batch4、图像尺寸640，初始化权重是公开parts.pt。类别数量改变时，Ultralytics会依据数据配置调整模型头，不能说只是把文件重命名成了10类模型。

## 第五步 正式训练并保留日志

数据和算力检查通过后，再制定正式epoch数。示例：

```powershell
& .\.venv\Scripts\python.exe scripts/train_parts.py --data $partsData --epochs 50 --device cpu --output runs/student2-parts10
```

已经另外配置好CUDA环境的机器，可以把`--device cpu`换为`--device 0`。不要只改参数而不检查PyTorch是否支持CUDA。

输出一般在指定project目录下的`train`子目录；若目录已存在，框架可能使用递增名称，应以控制台实际打印的保存路径为准。重点保留`weights/best.pt`、`weights/last.pt`、`results.csv`、训练曲线与参数记录。

## 第六步 区分best与last

best通常按验证集指标选择，last是最后一次保存。不能因为最后一个文件更新较晚，就认定它在测试集上更好。训练时不要用test划分反复挑选参数或最优轮次。

## 第七步 在10类测试集上评价新模型

先找到实际best.pt路径，再执行：

```powershell
$bestModel = (Resolve-Path .\runs\student2-parts10\train\weights\best.pt).Path
& .\.venv\Scripts\python.exe scripts/evaluate_parts.py --data $partsData --model $bestModel --device cpu --output results/tutorial-runs/parts10-metrics.json
```

这个命令使用10类数据评估10类模型，与第07章原始23类公开模型复测是不同实验。记录全部条件，不能直接用71.44%的原始23类Mask mAP50当新模型基线而不说明类别变化。

## 第八步 用新模型独立推理

教程版命令行支持显式模型路径：

```powershell
& .\.venv\Scripts\python.exe scripts/run_demo.py --parts-model $bestModel --image samples/damage-4.jpg --mode parts --output results/tutorial-runs/custom-model
```

部件名称必须采用工程支持的10类或原始细分类编码。若模型用了`car-door`等其他名称，需要先建立明确映射，不能静默丢弃未识别名称后声称正常工作。

## 第九步 接入网页并核对实际加载模型

先停止旧服务，再启动自选权重：

```powershell
& .\stop.ps1
& .\start.ps1 -PartsModel $bestModel
Invoke-RestMethod 'http://127.0.0.1:8765/api/health'
```

检查返回的`partsModelFile`是否为实际文件名，`partsSource`是否标记为用户指定权重，`nativeModelClasses`是否符合训练配置。只刷新网页不会自动让已运行的Python进程换模型。

要恢复默认公开模型，先停止服务、清除当前终端的自选路径，再启动：

```powershell
& .\stop.ps1
Remove-Item Env:STUDENT2_PARTS_MODEL -ErrorAction SilentlyContinue
& .\start.ps1
```

这一过程不覆盖原公开parts.pt，便于重复对比。新模型的训练材料和来源应单独记录，不能因为Demo能加载就认为训练或精度已经完成验证。

本章验收仅在真正执行后填写：训练日志、权重、10类测试指标、样例和失败案例均有实际文件。本次仓库默认只提供入口与方法，不预先填写这些训练成果。
