# 06 接口联调与字段说明

本章让学生1或业务后端通过接口调用学生2模块。先使用工程自带图片与JSON验证调用链，再替换为真实损伤识别结果。

## 第一步 启动并确认服务

```powershell
& .\start.ps1 -NoBrowser
Invoke-RestMethod 'http://127.0.0.1:8765/api/health'
```

返回`status=ok`后再发起预测。`GET /api/samples`列出内置图片；浏览器打开`http://127.0.0.1:8765/docs`可以看到自动生成的FastAPI接口文档。

## 第二步 明确请求格式

预测接口是`POST /api/predict`，使用`multipart/form-data`，不是把整张图片塞进普通JSON。

| 字段 | 类型 | 用途 |
| --- | --- | --- |
| file | 图片文件 | 必填的车辆照片 |
| mode | 字符串 | parts、auto、external |
| partConfidence | 数值 | 部件预测阈值，默认0.25 |
| damageConfidence | 数值 | auto模式损伤预测阈值，默认0.25 |
| minCoverage | 数值 | 最低匹配覆盖率，默认0.35 |
| damagesJson | JSON文本 | external模式的损伤数组 |

网页和接口允许的阈值范围为0.05至0.95。学生2的external模式接收损伤类型、位置和置信度，不负责证明这些损伤输入正确。

## 第三步 约定坐标与数据结构

示例`config/student1-example.json`为：

```json
[
  {"damageType":"dent","confidence":0.9,"bbox":[390,335,510,440]}
]
```

`bbox`用像素xyxy，两个角点依次为左上和右下，不是中心点加宽高，也不是0至1的归一化坐标。坐标必须对应同一张EXIF纠正后的原图，并满足`0≤x1<x2≤width`、`0≤y1<y2≤height`。

损伤类型建议沿用`dent`、`scratch`、`crack`、`glass_shatter`、`lamp_broken`、`tire_flat`。程序也允许其他非空类型字符串，但车灯、玻璃与轮胎语义限制只对既定名称生效。

如果学生1内部先缩小了照片，应把框还原到原图坐标后再传入。例如原图宽度是分析图宽度的两倍，x坐标也要乘二。若发生旋转或裁剪，还必须处理相应坐标变换，不能只乘一个比例。

## 第四步 先运行现成客户端

```powershell
& .\.venv\Scripts\python.exe examples/api_client.py
```

默认读取`damage-4.jpg`和示例JSON，向本地接口发送external请求。预期打印`parts=7, damages=1`附近的结果，并写入`results/tutorial-runs/api-result.json`。准确耗时不固定。

更换图片和损伤文件时：

```powershell
& .\.venv\Scripts\python.exe examples/api_client.py --image 'C:\你的图片目录\car.jpg' --damages-json 'C:\你的结果目录\damages.json' --mode external --output results/tutorial-runs/my-car.json
```

若端口改成8766，增加`--url http://127.0.0.1:8766`。使用工程客户端能避免Windows PowerShell 5与新版PowerShell在文件表单参数上的差异。

## 第五步 理解最小Python请求

```python
import json
import requests

damage = [{"damageType": "dent", "confidence": 0.9,
           "bbox": [390, 335, 510, 440]}]
with open('samples/damage-4.jpg', 'rb') as image:
    response = requests.post(
        'http://127.0.0.1:8765/api/predict',
        data={'mode': 'external', 'damagesJson': json.dumps(damage)},
        files={'file': ('car.jpg', image, 'image/jpeg')},
        timeout=120,
    )
response.raise_for_status()
result = response.json()
print(result['damages'])
```

上传文件的字段必须叫`file`；外部损伤数组要序列化成`damagesJson`文本。如果直接把Python列表当普通表单值发送，服务器不一定能正确解析。

## 第六步 读取返回结果

顶层有`width`、`height`、`mode`、`thresholds`、`model`、`parts`和`damages`。框与轮廓始终按返回尺寸解释。

| 损伤字段 | 解释 |
| --- | --- |
| damageId | 本次请求内的损伤编号 |
| part | 主部件编码，未确定时为unknown |
| partInstanceId | 对应parts中的具体实例 |
| matchCoverage | 部件覆盖该损伤区域的比例 |
| matchIou | 损伤框与主部件框的IoU |
| damageRatio | 交集占部件区域面积比例；未匹配为null |
| ratioMethod | mask_intersection、bbox_mask_intersection等计算分支 |
| matchStatus | matched、multiple_parts、unmatched |
| candidates | 候选部件、覆盖率、IoU及类型相容性 |

`semanticCompatible=false`的候选不会被选为主部件，但保留在候选信息中，方便解释为什么拒绝。

## 第七步 正确展示图片URL

返回的`partsImageUrl`与`matchingImageUrl`类似`/media/某编号-parts.jpg`。后端同学应在同一服务来源下拼接完整地址，例如`http://127.0.0.1:8765`加上该路径。

URL不等于永久存档。清理本机`data/media`后，旧链接可能失效。个人报告应把图片文件与JSON一起保存。

## 第八步 处理错误而不是伪造结果

HTTP422表示图片无法读取、模式或阈值无效、JSON或坐标不合法；HTTP413表示图片过大；连接失败通常表示服务没启动、端口不符或地址无法到达。

调用方应展示错误信息并允许重试，不应在错误时偷偷返回固定的保险杠结果。对unknown和空部件列表，也应显示待确认，而不是伪装成成功定位。

本章验收：自带external请求成功；一个非法框被拒绝；能把`partInstanceId`与部件实例对应；正确区分URL与实际文件。
