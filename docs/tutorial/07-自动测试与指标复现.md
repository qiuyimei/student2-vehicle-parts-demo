# 07 自动测试与指标复现

测试要分别回答“代码是否遵守约定”“模型能否运行”“部件识别精度如何”“损伤关联是否正确”。四个问题不能用同一个数字替代。

## 第一步 运行全部自动测试

```powershell
& .\.venv\Scripts\python.exe -m pytest -q
```

2026年10月25日教程版为31项测试通过。完整API测试会加载真实部件模型，所以需要parts.pt和项目依赖。初版报告记录的25项是10月15日的结果，新增5项检查数据归档提取边界，另增加1项自选模型路径元数据检查，不要混写日期。

| 测试文件 | 检查重点 |
| --- | --- |
| test_matching.py | 低IoU但高覆盖、无部件、掩膜面积、多候选、类型相容性 |
| test_parts.py | 左右冲突合并、分离实体保留、不同家族不合并 |
| test_inputs.py | 非法坐标与输入复制 |
| test_api.py | 损坏图片、非法阈值、越界框、真实external和parts调用 |
| test_dataset_download.py | ZIP路径越界、错误校验值、测试集筛选、数量异常 |

如果出现Starlette关于httpx的弃用提示，同时所有断言通过，应把它登记为依赖提示，不要将它写成测试失败。若存在FAILED，则先处理失败再提交“全部通过”的结论。

## 第二步 只运行不需要权重的测试

```powershell
& .\.venv\Scripts\python.exe -m pytest -q tests/test_matching.py tests/test_parts.py tests/test_inputs.py tests/test_dataset_download.py
```

GitHub Actions自动运行这一组轻量测试，只安装NumPy与pytest，不下载模型和全部数据。因此Actions通过不代表276张模型精度验证已经在云端重新执行。

## 第三步 运行9张演示图片

```powershell
& .\.venv\Scripts\python.exe scripts/batch_test.py
```

脚本会写出逐图JSON、部件和匹配图片、`batch-results.csv`与`batch-summary.json`。默认写入`results/`，会更新同名样例结果；若要保留历史，请先提交旧结果或复制一份，再运行。

初版记录是55个合并后部件、21个损伤输入、14个规则接受匹配。没有人工关联真值，不能把14/21写成匹配准确率。某些损伤预测本身可能错误，有的部件也会被误分类。

## 第四步 准备原始23类测试数据

```powershell
& .\.venv\Scripts\python.exe scripts/download_dataset.py --subset test
```

使用原始Carparts-seg test，不使用归并后的parts10。原因是公开模型类别ID仍对应23类；把10类标签交给它计算mAP，会造成类别含义不一致。

## 第五步 重新计算公开模型指标

```powershell
$publicDataset = (Resolve-Path .\data\datasets\carparts-seg).Path
& .\.venv\Scripts\python.exe scripts/evaluate_public_test.py --dataset $publicDataset
```

这一步计算原始公开部件模型的指标，不会训练模型。默认CPU、640推理尺寸、batch4、test划分。程序写出`results/public-model-metrics-rerun.json`，图表在`results/public-model-eval/`。重新生成图表会更新同名文件。

原始正式记录在`results/public-model-metrics.json`，包含模型和数据包SHA256。初版结果：

| 指标 | 框 | 掩膜 |
| --- | --- | --- |
| Precision | 62.48% | 62.87% |
| Recall | 82.08% | 82.40% |
| mAP50 | 71.18% | 71.44% |
| mAP50至95 | 60.57% | 58.16% |

Precision和Recall的统计定义取决于验证器采用的置信度选择，不能与网页单张图片上的置信度混用。更换数据版本、模型或推理参数后，应登记新实验，而不是修改旧报告里的数值。

## 第六步 读懂图表

PR曲线表示不同阈值下Precision与Recall的关系；F1曲线用于观察阈值变化；混淆矩阵用于发现类别间混淆；`val_batch*_labels.jpg`和`val_batch*_pred.jpg`让你比较标注与预测。

左、右车门或车灯的混淆，应结合照片方向检查，不能只看总体mAP。通用object类别与业务明确部件也应分开解释。

## 第七步 验证损伤与部件关联

当前工程自动测试覆盖了算法分支，但尚未建成新的人工标注“损伤→部件”独立测试集。后续应为每一处损伤登记正确部件实例、是否跨部件、是否侧别可判定，再对比程序结果。

至少记录正确主部件、错误主部件、合理unknown、不合理unknown、多部件情况。这样才能讨论关联模块的准确率与拒识表现。

## 第八步 保存可复查记录

每个实验保留日期、输入数据与划分、权重SHA256、参数、运行命令、输出JSON、至少一个失败样例。保存命令示例：

```powershell
Get-FileHash .\models\parts.pt -Algorithm SHA256
& .\.venv\Scripts\python.exe -m pytest -q --junitxml results/tutorial-runs/pytest.xml
```

本章验收：区分代码测试和模型精度；没有把接受数当准确率；能重新生成指标；知道原始23类和转换10类不能混评。
