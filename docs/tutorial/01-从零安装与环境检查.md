# 01 从零安装与环境检查

本章以Windows PowerShell和Python 3.12为例。每次执行命令前，先确认自己位于工程根目录，也就是能看到`README.md`、`requirements.txt`和`ai`文件夹的位置。

## 第一步 获取源码

打开PowerShell，先选择一个自己有写权限的项目文件夹。例如：

```powershell
$projectBase = Join-Path ([Environment]::GetFolderPath('MyDocuments')) 'student2-projects'
New-Item -ItemType Directory -Path $projectBase -Force | Out-Null
Set-Location -LiteralPath $projectBase
git clone https://github.com/qiuyimei/student2-vehicle-parts-demo.git
Set-Location .\student2-vehicle-parts-demo
```

成功时会生成`student2-vehicle-parts-demo`目录。若提示仓库不存在或无权限，先确认浏览器登录的账号有该私有仓库访问权；这不是Python安装问题。也可以在仓库的Code菜单下载ZIP，完整解压后进入工程目录。

执行：

```powershell
Get-Location
Get-ChildItem
```

应能看到`ai`、`web`、`scripts`、`tests`和`requirements.txt`。如果只能看到一个同名文件夹，说明还停留在解压包外层，需要再进入一层。

## 第二步 确认Python解释器

```powershell
py -3.12 --version
py -3.12 -c 'import sys; print(sys.executable)'
```

第一条应显示`Python 3.12.x`，第二条给出真正的Python可执行文件路径。若没有`py`命令，找到已安装的Python 3.12，使用它的完整路径，例如：

```powershell
& 'C:\你的Python目录\python.exe' --version
```

不要把`python.exe`所在文件夹当成可执行文件本身。本工程初版验证环境为Python 3.12.14，尚未声称Python 3.14环境已经通过全部测试。

## 第三步 设置本终端使用UTF8

```powershell
$env:PYTHONUTF8 = '1'
$env:PYTHONIOENCODING = 'utf-8'
```

这能减少命令行重定向中文日志时的编码混淆，只影响当前终端及其启动的子进程。下次新开终端可以再次执行。

## 第四步 选择自动安装或手动安装

已经确认`py -3.12`可用时，自动安装命令为：

```powershell
$pythonPath = py -3.12 -c 'import sys; print(sys.executable)'
powershell.exe -NoProfile -ExecutionPolicy Bypass -File .\setup.ps1 -PythonPath $pythonPath
```

脚本依次创建`.venv`、安装CPU PyTorch、安装项目依赖、下载并校验模型。只对这次PowerShell进程设置脚本执行方式，不需要永久修改系统策略。

若Python解释器路径已知，也可以直接把`-PythonPath`参数换成完整路径。任一步安装失败时，脚本会停止；先处理错误，不要把“执行过命令”当成安装成功。

想理解每一步时，手动执行下列命令，手动与自动方式二选一即可：

```powershell
py -3.12 -m venv .venv
& .\.venv\Scripts\python.exe -m pip --version
& .\.venv\Scripts\python.exe -m pip install torch==2.14.1 torchvision==0.29.1 --index-url https://download.pytorch.org/whl/cpu
& .\.venv\Scripts\python.exe -m pip install -r requirements.txt
& .\.venv\Scripts\python.exe scripts/download_models.py
```

本教程始终明确调用`.venv`里的Python，因此不要求先激活环境，也能避免把依赖装到另一个Python中。

## 第五步 理解为什么分两次安装依赖

第一条安装命令从[PyTorch CPU官方索引](https://pytorch.org/get-started/locally/)安装本次验证过的CPU版本。第二条根据`requirements.txt`安装YOLO、FastAPI等依赖。`requirements-lock.txt`保留初版完整环境登记，其中的`+cpu`包不应脱离CPU索引盲目安装。

首次安装需要网络与磁盘空间。模型和依赖准备好后，Demo的本地推理不需要联网。CPU版本能够复现本项目的演示；它不能因为电脑有NVIDIA显卡就自动变成CUDA训练环境。

## 第六步 检查模型文件

```powershell
Get-ChildItem .\models
& .\.venv\Scripts\python.exe scripts/doctor.py --strict
```

正常输出中应有`python312: true`，各依赖应显示版本号，`parts.pt`和`damage.pt`的`verified`均为`true`，`sampleCount`为9，`readyForAllDemos`为`true`。

环境检查登记依赖版本、模型校验值和样例数量；它还不能代替真正的推理测试。模型大小与SHA256见[模型说明](../../models/README.md)。若模型校验失败，不要直接删除校验代码：可能是下载不完整、拿错权重或上游地址更新，先保留错误并核对文件。

## 第七步 验证主要库能真正导入

```powershell
& .\.venv\Scripts\python.exe -c 'import torch, cv2, numpy, ultralytics, fastapi; print(torch.__version__); print(torch.cuda.is_available())'
```

本教程安装CPU版本，`torch.cuda.is_available()`返回`False`是正常的。若报DLL或找不到模块，先核对命令是否调用`.venv`里的Python，再按[常见问题](10-常见问题逐项排查.md)排查。

本章验收：已进入正确目录；Python版本确认；依赖安装无失败；权重校验通过；主要库能够导入。
